This site started from the open source [Magic UI portfolio template](https://github.com/magicuidesign/portfolio). I kept the design and changed what sits underneath so it could run on GitHub Pages instead of Vercel.

## The stack

- **Next.js 16** with the App Router
- **Tailwind CSS v4** and a few shadcn/ui components
- **Motion** for the blur and fade animations
- **Content Collections** to turn MDX files into typed posts

All of the personal data lives in one file, `src/data/resume.tsx`. Projects, education, links and skills are plain objects there, and the pages just map over them.

## Static export

GitHub Pages only serves files. There is no Node server, so the whole site has to be HTML, CSS and JavaScript by the time it is uploaded. Next.js supports this with one line:

```js title="next.config.mjs"
const nextConfig = {
  output: "export",
  trailingSlash: true,
  images: { unoptimized: true },
};
```

That change had a few side effects.

1. **No request data on the server.** The blog index used to read `?page=2` from `searchParams` on the server. In a static build there is no request, so the list moved into a client component that reads the page number with `useSearchParams`.
2. **Open Graph images are rendered at build time.** They used to run on the edge and fetch fonts over the network. Now they read the font files and my photo straight from disk while the site builds.
3. **No custom headers.** `headers()` in the Next config does nothing on a static host, so I removed it rather than keep config that looks like it works.

## Deploying

A single workflow in `.github/workflows` handles everything. On a pull request it runs the linter, the type checker, a full build and a link check over the exported HTML. On a push to `main` it also publishes the `out` folder with `actions/deploy-pages`, then loads the live home page and requests every stylesheet, script and image it references.

That last step exists because of a mistake I made early on. The site first went up under `devpilotx.github.io/devpilotX`, so every asset URL started with `/devpilotX`. When I moved to `devpilotx.me` the HTML still pointed there, the build passed, and the live page loaded without any of its CSS or JavaScript. Now a wrong base path fails the link check, and a broken deploy fails the smoke test.

Adding a post is a new `.mdx` file in `content`. Pushing it to `main` is the whole release process.
