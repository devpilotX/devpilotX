## About this site

## How a change goes live

```mermaid
flowchart LR
  push(["Push to main"]) --> cf["Cloudflare Pages: pnpm build"]
  cf --> live(["devpilotx.me"])
  push --> ci["CI: lint, build, type check, link and SEO checks"]
  pr(["Pull request"]) --> ci
  ci -->|"on main"| smoke{"Live check"}
  live --> smoke
```

- Cloudflare Pages builds every push to `main` with `pnpm build` and publishes `out/`. It does not wait for CI, so run `pnpm check` before you push.
- CI runs the same checks on pull requests and on `main`. On `main` it then waits until devpilotx.me carries the new commit's build ID, requests the page's assets, the main pages and a made-up URL that must answer 404, and checks the security headers.
- To roll back, open the Pages project in the Cloudflare dashboard, go to **Deployments** and choose **Rollback to this deployment** on the last good one. The switch is instant. Reverting the commit and pushing works too.

## Quick start

You need Node.js 20.9 or newer and pnpm 10.

```bash
pnpm install
pnpm dev
```

Open http://localhost:3000. Edit `src/data/resume.tsx` and the page updates as you save.

## Everyday commands

| Command | What it does |
| --- | --- |
| `pnpm dev` | Development server at http://localhost:3000. Google Analytics stays off |
| `pnpm build` | Static export into `out/`. Two scripts then copy the router's segment files to the flat names the browser asks for, and delete source maps |
| `pnpm preview` | Serves `out/` with Cloudflare's Pages emulator at http://localhost:8788, with `_headers` and `_redirects` applied. The first run downloads Wrangler |
| `pnpm lint` | ESLint |
| `pnpm typecheck` | TypeScript. It needs the post types that `pnpm build` or `pnpm dev` generates |
| `pnpm check:links` | Every `href`, `src` and `srcset` in `out/` points at a file that exists |
| `pnpm check:seo` | Titles, descriptions, canonical URLs, sharing tags, JSON-LD and the sitemap of every page |
| `pnpm check` | All of it in order: lint, build, type check, links, SEO |

## Writing a post

Posts are MDX files in [`content/`](content). The file name becomes the address, so `content/my-first-post.mdx` is published at `devpilotx.me/blog/my-first-post/`.

````md
---
title: "Your post title"
publishedAt: "2026-11-02"
summary: "One or two sentences. They appear on the blog page, in search results and on the sharing card."
---

Write in Markdown. Tables, task lists and code blocks work, and a code block can have a title:

```bash title="setup.sh"
sudo apt install nginx
```
````

| Field | Required | What it does |
| --- | --- | --- |
| `title` | Yes | The heading, the page title and the title on the sharing card |
| `publishedAt` | Yes | The date, as `YYYY-MM-DD`. Posts are listed newest first |
| `summary` | Yes | Shown on the blog page and the sharing card, and used as the meta description |
| `updatedAt` | No | Adds "Updated" under the date and moves the post's date in the sitemap |
| `image` | No | A root-relative path to your own 1200×630 image in `public/`. Without it, one is rendered at build time |

Run `pnpm dev` and open http://localhost:3000/blog/ to read it, then push to `main`. Once Cloudflare has built it, the post is on the blog page, among the three latest posts on the home page, in the RSS feed, the sitemap and `llms.txt`, and it has its own sharing image. Every post ends with links to share it on X and LinkedIn and a button that copies its address.

There is no draft flag, so keep unfinished posts out of `content/`.

## Project layout

```text
src/app          pages, sharing images, sitemap, robots.txt, RSS, llms.txt and the web manifest
src/components   site components; section/ holds the home page sections
src/data         resume.tsx (profile, links, work, education, skills) and projects.ts
src/lib          SEO helpers, the sharing card renderer and blog helpers
src/assets       project screenshots, sharing card covers and the fonts the cards use
content          blog posts in MDX
public           the mascot, icons, _headers, _redirects and the Search Console file
scripts          build clean-up, and the link, SEO and live-site checks
.github          the CI workflow, the funding link and the screenshots in this README
```

## Good to know

- Search Console reads `public/google3419091e9a1248e3.html` and the `google-site-verification` tag in `src/app/layout.tsx`, so keep both. Cloudflare Pages redirects addresses that end in `.html`, and Search Console does not follow redirects for this file, so `public/_redirects` serves it in place.
- Google Analytics 4 loads only in production builds, so local work does not show up in the reports.
- Screenshots of the Techcyme CRM, Maanak and quantsys use sample or demo data.
- The design started from the open source [portfolio template by Dillion Verma](https://github.com/magicuidesign/portfolio). Both are released under the [MIT license](LICENSE).
